## 목표

로봇 개발에 쓰이는 도구의 역할을 구분하고, 필요한 순서대로 학습한다. 모든 도구를 처음부터 배울 필요는 없다. 이 페이지는 도구 개요이며 특정 교육과정의 필수 도구 목록은 아니다.

## 1. 운영체제와 실행 환경

| 도구 | 역할 | 학습 시점 |
|---|---|---|
| Ubuntu | ROS 2와 로봇 개발 도구를 실행하는 Linux 운영체제 | 환경 준비 |
| WSL 2 | Windows 안에서 Ubuntu 같은 Linux 환경을 실행 | 환경 준비 |

WSL 2는 실행 환경이고 Ubuntu는 그 안에서 사용하는 운영체제다. 설치 전 Ubuntu·ROS 2 배포판·시뮬레이터의 지원 버전과 실행 환경을 확인한다.

## 2. 프로그래밍 언어

| 언어 | 역할 | 학습 시점 |
|---|---|---|
| Python | 동작 판단, AI 연결, 데이터 처리, 실험 코드 작성 | 먼저 학습 |
| C++ | 빠른 처리와 성능이 중요한 로봇 프로그램 작성 | 필요할 때 추가 |

ROS 2에서는 Python 노드와 C++ 노드를 함께 사용할 수 있다. Python으로 작은 기능부터 만들고, 측정 결과 성능 개선이 필요한 부분에 C++을 적용한다. C++ 사용만으로 실시간 동작이 보장되는 것은 아니다.

## 3. 로봇 소프트웨어

| 도구 | 역할 | 학습 시점 |
|---|---|---|
| ROS 2 | 센서·인식·판단·모터 제어 프로그램 사이의 통신과 실행을 지원 | 핵심 학습 |
| RViz 2 | 센서 데이터, 로봇 모델, 좌표계 등을 시각화 | 데이터 확인 단계 |

ROS는 Robot Operating System의 약자이며 ROS 2는 두 번째 세대다. 일반적인 운영체제 대신 로봇 개발용 라이브러리와 도구 모음으로 이해하면 된다.

노드는 기능을 수행하는 프로그램 단위이고, 토픽은 메시지를 주고받는 이름 붙은 통로다. 예를 들어 거리 센서 노드가 거리를 보내면 판단 노드가 정지 여부를 결정하고 모터 제어 노드에 속도 명령을 전달한다.

RViz 2는 데이터를 보여주는 도구이며 물리 시뮬레이터는 아니다.

## 4. 로봇 모델과 기구 설계

| 도구 / 형식 | 역할 | 학습 시점 |
|---|---|---|
| CAD | 부품의 모양·치수·조립 구조와 제작 도면 설계 | 직접 기구를 설계할 때 |
| URDF | 부품, 관절, 연결 관계와 물리 속성을 정의하는 파일 형식 | 로봇 모델 구성 |
| Xacro | 변수와 매크로로 URDF를 간결하게 작성하는 도구 | 모델이 복잡해질 때 |

CAD는 특정 제품명이 아니라 설계 도구의 종류다. CAD 형상만으로 제어용 로봇 모델이 완성되지는 않으며 관절, 질량, 관성, 충돌 형상 등의 정보도 필요하다. 기존 로봇 모델을 쓰면 CAD를 능숙하게 다루기 전에도 실습할 수 있다.

## 5. 시뮬레이션

| 도구 | 역할 | 학습 시점 |
|---|---|---|
| NVIDIA Isaac Sim | 가상 로봇·센서·환경을 구성하고 물리적인 동작을 시험 | 가상 실험 단계 |

ROS 2와 연결하면 다음 흐름으로 시험할 수 있다.

가상 센서 → ROS 2에서 데이터 수신·판단 → 제어 명령 → 가상 로봇 동작 → 센서 피드백

Isaac Sim이 시뮬레이션하는 대상은 로봇과 환경이다. ROS 2 프로그램을 여기에 연결해 시험한다. ROS 2 입문에 반드시 필요한 도구는 아니며 설치 환경과 GPU 요구사항은 사용할 버전의 공식 문서에서 확인한다.

## 6. 코드와 학습 기록 관리

| 도구 / 형식 | 역할 | 학습 시점 |
|---|---|---|
| Git | 코드·설정·문서의 변경 이력 관리 | 처음부터 |
| Markdown | 학습노트·설계서·실험 기록 작성 | 처음부터 |

실습 기록에는 목표, 환경과 버전, 실행 방법, 관찰 결과, 오류와 해결 방법, 다음 할 일을 남긴다.

## 7. AI 개발 도우미

| 도구 | 활용 | 학습 시점 |
|---|---|---|
| Claude / Codex | 개념 설명, 설계 초안, 코드·설정 작성, 오류 분석, 학습노트 정리 | 전 과정 |

파일과 코드를 생성하는 작업과 앱을 직접 조작하는 작업은 다르다. 직접 연결은 도구가 제공하는 API·CLI·플러그인 등의 지원 여부에 따라 달라진다. 생성된 코드와 설계는 실행, 시각화와 실험으로 확인한다.

## 추천 학습 흐름

1. WSL 2와 Ubuntu에서 개발 환경을 준비한다.
2. Python으로 기본 문법과 데이터 처리를 익힌다.
3. ROS 2 노드 두 개로 메시지를 주고받는다.
4. RViz 2에서 데이터와 기존 로봇 모델을 확인한다.
5. 필요에 따라 시뮬레이터와 연결한다.
6. 성능이 필요한 기능은 C++을 학습해 개선한다.
7. 직접 부품 제작이 필요하면 CAD와 로봇 모델 정의를 학습한다.

Git과 Markdown 기록은 전 과정에서 함께 사용한다.
